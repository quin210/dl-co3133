One pipeline, five architectures

Five architectures classify 28 × 28 grayscale Fashion-MNIST images into ten classes, using the same inputs, split, optimizer, training budget and evaluation.

IDX images and labels
  → fixed stratified training / validation split
  → normalization fitted on training pixels
  → Dataset and DataLoader
  → model → ten raw class scores → cross-entropy
  → Adam updates over 16 epochs
  → highest validation macro-F1 selects the checkpoint
  → selected weights evaluated on the official test set

The project defines data preparation, architectures and training/evaluation. PyTorch supplies layers, differentiation and Adam; NumPy handles arrays, scikit-learn splits/metrics, and Matplotlib figures.

Data and inputs

A seed-42 stratified split divides 60,000 official training images into 54,000 training and 6,000 validation images; the 10,000-image test set is unchanged. Each class contributes 5,400, 600 and 1,000 images respectively. No images are removed or relabeled.

Checkpoints store disjoint training/validation indices. Test data neither selects weights nor fits normalization. Product identifiers are unavailable, so image-index separation cannot establish product-level independence.

x = (pixel / 255 − training_mean) / training_std
training_mean = 0.286209    training_std = 0.353160

images: float32 [B, 1, 28, 28]
labels: int64   [B]          values 0 … 9
logits: float32 [B, 10]      output of every model

Training-only statistics normalize images once in the dataset constructor. Batch size is 128, with partial batches retained. Only training shuffles, using a seeded generator; loaders use zero workers. No resizing, augmentation or feature extraction precedes the models. See data exploration for the supporting analysis.

Model definitions

B denotes batch size. Every model returns ten raw logits. Softmax is used for inspection probabilities, never before cross-entropy.

Linear: a weighted pixel baseline

Each class receives a weighted sum of 784 pixels plus a bias, z = Wx + b. Without hidden features, the model cannot express nonlinear pixel interactions.

[B, 1, 28, 28] → Flatten → [B, 784]
              → Linear(784, 10) → [B, 10]
parameters = 784 × 10 + 10 = 7,850

Linear source

MLP: nonlinear combinations of pixels

A hidden layer learns 256 features: h = max(0, W₁x + b₁), then z = W₂h + b₂. ReLU zeros negative activations, enabling nonlinear decision boundaries without explicitly representing spatial neighborhoods.

[B, 1, 28, 28] → Flatten → [B, 784]
              → Linear(784, 256) → ReLU → [B, 256]
              → Linear(256, 10) → [B, 10]
parameters = (784 × 256 + 256) + (256 × 10 + 10)
           = 203,530

MLP source

CNN: local patterns with shared filters

Two blocks learn local features with shared 3 × 3 filters, ReLU and 2 × 2 max pooling, followed by a dense classifier. Padding of one preserves spatial size during convolution.

[B, 1, 28, 28]
  → Conv2d(1, 16, kernel=3, padding=1) → ReLU
  → MaxPool2d(2) → [B, 16, 14, 14]
  → Conv2d(16, 32, kernel=3, padding=1) → ReLU
  → MaxPool2d(2) → [B, 32, 7, 7]
  → Flatten → [B, 1568]
  → Linear(1568, 64) → ReLU → Linear(64, 10) → [B, 10]

CNN source

LSTM: reading the image row by row

A single 64-unit LSTM reads 28 image rows from top to bottom. Gates control new and retained information: cₜ = fₜ ⊙ cₜ₋₁ + iₜ ⊙ gₜ, hₜ = oₜ ⊙ tanh(cₜ). The final hidden state feeds the classifier. This representation prioritizes row order over two-dimensional neighborhoods.

[B, 1, 28, 28] → squeeze channel → [B, 28, 28]
              → LSTM(input_size=28, hidden_size=64, layers=1)
              → final hidden state [B, 64]
              → Linear(64, 10) → [B, 10]

LSTM source

Transformer: attention across image patches

Each of 49 non-overlapping 4 × 4 patches becomes a 32-value token with a learned position embedding. Two encoders use four attention heads, feed-forward width 64, residual connections and layer normalization. With eight values per head, Attention(Q, K, V) = softmax(QKᵀ / √dₖ)V connects distant patches; position embeddings preserve spatial identity.

[B, 1, 28, 28] → 7 × 7 patches → [B, 49, 16]
              → Linear(16, 32) + learned positions [1, 49, 32]
              → two Transformer encoder layers → [B, 49, 32]
              → mean over 49 tokens → [B, 32]
              → Linear(32, 10) → [B, 10]

Encoders use ReLU and zero dropout; classification uses mean pooling without a class token. No pretrained weights are used.

Training and selection

Settings shared by all five models
SettingValue
Random seed42 for Python, NumPy and PyTorch; training shuffle also uses 42
OptimizerAdam, learning rate 0.001
Budget16 epochs, batch size 128; every epoch runs
Gradient clippingMaximum total gradient norm 5.0
SelectionHighest validation macro-F1; earliest epoch wins an exact tie
RegularizationNo augmentation, dropout, weight decay or learning-rate scheduler
ExecutionCPU, four PyTorch threads, float32, deterministic algorithms enabled

Each batch clears gradients, computes cross-entropy, backpropagates, clips gradients and updates with Adam. Non-finite losses or gradients raise errors. Validation follows each epoch in evaluation mode without gradients.

Reported metrics use selected weights in best.pt; checkpoint.pt stores epoch-16 weights. Test results do not select checkpoints.

Comparison scope: architecture changes both capacity and image representation. This is not a capacity-matched ablation or hyperparameter search; equal epochs do not imply equal compute or optimization difficulty.

History records predictions while weights change. Checkpoint training metrics use fixed selected weights, so they may differ from that epoch's history.

Loss, metrics and timing

For logits z and target y, cross-entropy is −z[y] + log(Σₖ exp(z[k])). Batch loss is averaged; epoch loss weights batches by image count. Prediction uses argmax(z) without post-processing.

  • Accuracy: correct predictions divided by the number of images.
  • Macro-F1: unweighted mean of ten class scores, F1 = 2TP / (2TP + FP + FN); undefined scores are zero.
  • Training time: the 16-epoch training and validation loop, including history writes and copies of best weights. It excludes dataset preparation, post-training fixed-weight metrics and final artifact generation.
  • Inference time: the median of three complete batched passes after one warmup, divided by image count. It includes DataLoader iteration, the forward pass and argmax; it excludes metric calculation.

Inference measures batched CPU throughput, not single-request latency. Measurements appear in results and analysis.

Recorded environment

All runs record Python 3.12.13, PyTorch 2.14.0, NumPy 2.5.3 and scikit-learn 1.9.1 on macOS-26.6.2-arm64-arm-64bit, using four CPU threads. Processor model and memory are not recorded. Notebook and plotting dependencies are pinned below.

Reproduce the experiment

From the dl-co3133 repository root. Training creates new timestamped folders; evaluation refreshes metrics and predictions in every saved model folder containing best.pt.

Train and evaluate all five models

python3.12 -m venv .venv

.venv/bin/python Assignment1/download.py
.venv/bin/python Assignment1/data_loader.py
.venv/bin/python Assignment1/train.py
.venv/bin/python Assignment1/evaluate.py

The loader prints split sizes, tensor shapes and normalization statistics. Training order: Linear, MLP, CNN, LSTM, Transformer.

Train and evaluate only the M1 baselines

After setup and data download, train Linear and MLP with the same settings, resetting the seed before each model.

.venv/bin/python - <<'PY'
import sys
sys.path.insert(0, "Assignment1")
from train import set_seed, fit
from evaluate import evaluate
from models.linear import LinearClassifier
from models.mlp import MLP

for name, Model in [("Linear", LinearClassifier), ("MLP", MLP)]:
    set_seed(42)
    folder = fit(Model(), name, seed=42)
    evaluate(Model(), folder)
PY

Reconstruct a saved model without retraining

Reload the retained CNN with its saved split and normalization to measure test accuracy and macro-F1. Change folder for another model.

.venv/bin/python - <<'PY'
import sys
from pathlib import Path
import torch
sys.path.insert(0, "Assignment1")
from data_loader import get_data_loaders
from evaluate import predict
from models.linear import LinearClassifier
from models.mlp import MLP
from models.cnn import CNN
from models.lstm import LSTMClassifier
from models.transformer import TransformerClassifier

classes = {"Linear": LinearClassifier, "MLP": MLP, "CNN": CNN,
           "LSTM": LSTMClassifier, "Transformer": TransformerClassifier}
folder = Path("Assignment1/outputs/CNN_seed42_20260921_102822_896256")
saved = torch.load(folder / "best.pt", map_location="cpu", weights_only=True)
info, data = saved["info"], saved["data"]
torch.set_num_threads(info["threads"])
torch.use_deterministic_algorithms(True)
model = classes[info["model"]]()
model.load_state_dict(saved["model_state"])
model.eval()
_, validation, test, _ = get_data_loaders(
    batch_size=info["batch_size"], seed=info["seed"],
    split=data, normalization=data,
)
metrics, labels, predictions, probabilities = predict(model, test)
print("Selected weight epoch:", saved["epoch"])
print(metrics)
PY

Top-level epoch identifies saved weights; info describes the run and selected checkpoint, even in the final-weight file. Optimizer state is absent, so reloading does not restore Adam's training state.

Limitations

One seed, split and 16-epoch budget cannot establish training variability, a statistically reliable ranking or optimal configurations. Repeated seeds would permit mean and spread estimates.

Saved preprocessing and deterministic algorithms support repeatability, but software and hardware can affect results and timings. Small grayscale catalog images limit generalization to color, high-resolution detail and real-world scenes.
