1. One pipeline, five architectures

Five architectures classify 28 × 28 grayscale Fashion-MNIST images into ten classes. They use the same inputs, split, optimizer, training budget and evaluation. Each architecture trains once for each of five seeds, 42 to 46. Nine extension models use the same pipeline.

IDX images and labels
  → fixed stratified training / validation split
  → normalization fitted on training pixels
  → Dataset and DataLoader
  → model → ten raw class scores → cross-entropy
  → Adam updates over 16 epochs
  → highest validation macro-F1 selects the checkpoint
  → selected weights evaluated on the official test set

The project defines data preparation, architectures and training/evaluation. PyTorch supplies layers, differentiation and Adam; NumPy handles arrays, scikit-learn splits/metrics, and Matplotlib figures.

2. Data and inputs

A seed-42 stratified split divides 60,000 official training images into 54,000 training and 6,000 validation images; the 10,000-image test set is unchanged. Each class contributes 5,400, 600 and 1,000 images respectively. No images are removed or relabeled.

Checkpoints store disjoint training/validation indices. Test data neither selects weights nor fits normalization. Product identifiers are unavailable, so image-index separation cannot establish product-level independence.

images: float32 [B, 1, 28, 28]
labels: int64   [B]          values 0 … 9
logits: float32 [B, 10]      output of every model

Training-only statistics normalize images once in the dataset constructor. Batch size is 128, with partial batches retained. Only training shuffles, using a seeded generator; loaders use zero workers. No resizing, augmentation or feature extraction precedes the models. See data exploration for the supporting analysis.

3.1 Linear: a weighted pixel baseline

Each class receives a weighted sum of 784 pixels plus a bias, z = Wx + b. Without hidden features, the model cannot express nonlinear pixel interactions.

Assignment1/models/linear.pyclass LinearClassifier(nn.Module):
    # one score per class from the raw pixel vector
    def __init__(self):
        super().__init__()
        self.layers = nn.Sequential(
            nn.Flatten(), nn.Linear(784, 10)
        )

    def forward(self, images):
        return self.layers(images)

3.2 MLP: nonlinear combinations of pixels

A hidden layer learns 256 features: h = max(0, W₁x + b₁), then z = W₂h + b₂. ReLU zeros negative activations, enabling nonlinear decision boundaries without explicitly representing spatial neighborhoods.

Assignment1/models/mlp.pyclass MLP(nn.Module):
    # a nonlinear baseline without spatial assumptions
    def __init__(self):
        super().__init__()
        self.layers = nn.Sequential(
            nn.Flatten(),
            nn.Linear(784, 256),
            nn.ReLU(),
            nn.Linear(256, 10),
        )

    def forward(self, images):
        return self.layers(images)

3.3 CNN: local patterns with shared filters

Two blocks learn local features with shared 3 × 3 filters, ReLU and 2 × 2 max pooling, followed by a dense classifier. Padding of one preserves spatial size during convolution.

Assignment1/models/cnn.pyclass CNN(nn.Module):
    # shared filters preserve local image structure
    def __init__(self):
        super().__init__()
        self.layers = nn.Sequential(
            nn.Conv2d(1, 16, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),
            nn.Conv2d(16, 32, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),
            nn.Flatten(),
            nn.Linear(32 * 7 * 7, 64),
            nn.ReLU(),
            nn.Linear(64, 10),
        )

    def forward(self, images):
        return self.layers(images)

3.4 LSTM: reading the image row by row

A single 64-unit LSTM reads 28 image rows from top to bottom. Gates control new and retained information: cₜ = fₜ ⊙ cₜ₋₁ + iₜ ⊙ gₜ, hₜ = oₜ ⊙ tanh(cₜ). The final hidden state feeds the classifier. This representation prioritizes row order over two-dimensional neighborhoods.

Assignment1/models/lstm.pyclass LSTMClassifier(nn.Module):
    # image rows form a sequence from top to bottom
    def __init__(self):
        super().__init__()
        self.lstm = nn.LSTM(
            input_size=28,
            hidden_size=64,
            num_layers=1,
            batch_first=True,
        )
        self.classifier = nn.Linear(64, 10)

    def forward(self, images):
        rows = images.squeeze(1)
        _, (hidden, _) = self.lstm(rows)
        return self.classifier(hidden[-1])

3.5 Transformer: attention across image patches

Each of 49 non-overlapping 4 × 4 patches becomes a 32-value token with a learned position embedding. Two encoders use four attention heads, feed-forward width 64, residual connections and layer normalization. With eight values per head, Attention(Q, K, V) = softmax(QKᵀ / √dₖ)V connects distant patches; position embeddings preserve spatial identity.

Assignment1/models/transformer.pyclass TransformerClassifier(nn.Module):
    # attention combines patches with learned spatial positions
    def __init__(self):
        super().__init__()
        self.projection = nn.Linear(16, 32)
        self.positions = nn.Parameter(
            torch.empty(1, 49, 32)
        )
        nn.init.normal_(self.positions, std=0.02)
        layer = nn.TransformerEncoderLayer(
            d_model=32,
            nhead=4,
            dim_feedforward=64,
            dropout=0.0,
            batch_first=True,
        )
        self.encoder = nn.TransformerEncoder(
            layer, num_layers=2, enable_nested_tensor=False
        )
        self.classifier = nn.Linear(32, 10)

    def forward(self, images):
        patches = images.unfold(2, 4, 4).unfold(3, 4, 4)
        patches = patches.reshape(images.shape[0], 49, 16)
        tokens = self.projection(patches) + self.positions
        return self.classifier(
            self.encoder(tokens).mean(dim=1)
        )

4.1 Shift and noise augmentation

The five Augmented models change each training image every time the model reads it:

  • Shift: the image moves by a random integer dy and dx in {−2, …, 2} px. Background values fill the empty pixels. 24 of 25 draws move the image.
  • Noise: after the shift, each image gets Gaussian noise with probability 0.5, so about half of the images get noise. The noise has σ = 0.10 on the [0, 1] pixel scale. The result is clipped to the pixel range.
  • Scope: augmentation applies in training mode only. Validation, test and checkpoint selection use clean images.

The same models get both changes, so their effects cannot be separated. metrics.json records "augmentation": null for these runs, because train.fit writes a fixed value. The real augmentation is in models/augmented.py.

4.2 Post-results analysis protocol

The post-results analysis loads the saved best.pt checkpoints and test_predictions.npz files. It trains nothing.

  • Five-seed errors: per-class F1, confusion matrices and repeated errors over the 25 main runs.
  • Corruptions: noise (σ = 0.05, 0.10, 0.20), shift (1, 2, 3 px up, down, left, right), occlusion (one 8 × 8 or 12 × 12 px square) and contrast (× 0.75, × 0.5). Fixed random seeds give every model and seed the same test images.
  • Check: the clean pass must reproduce the test macro-F1 in metrics.json. Otherwise the analysis stops.
  • Saved scores: the analysis writes the scores once to Assignment1/outputs/robustness_scores.csv. A later run evaluates only the models that are not in this file.
  • Interpretability: occlusion sensitivity on a maximum of 300 test images, an LSTM row probe and Transformer attention weights.

Each batch clears gradients, computes cross-entropy, backpropagates, clips gradients and updates with Adam. Non-finite losses or gradients raise errors. Validation follows each epoch in evaluation mode without gradients.

Reported metrics use selected weights in best.pt; checkpoint.pt stores epoch-16 weights. Test results do not select checkpoints.

Comparison scope: the five main models give the main comparison. In this comparison, the architecture changes both the parameter count and the image representation. The matched-parameter ablation removes the parameter-count difference at about 25k parameters. There is no hyperparameter search. Equal epochs do not mean equal compute or equal optimization difficulty.

History records predictions while weights change. Checkpoint training metrics use fixed selected weights, so they may differ from that epoch's history.

5.1 Matched-parameter ablation

The main CNN has more parameters than LSTM and Transformer. The ablation asks a question: does CNN win because of its spatial design or because of its size? The hypothesis: with about 25k parameters for each model, CNN still has the highest macro-F1.

6. Loss, metrics and timing

For logits z and target y, cross-entropy is −z[y] + log(Σₖ exp(z[k])). Batch loss is averaged; epoch loss weights batches by image count. Prediction uses argmax(z) without post-processing.

  • Accuracy: correct predictions divided by the number of images.
  • Macro-F1: unweighted mean of ten class scores, F1 = 2TP / (2TP + FP + FN); undefined scores are zero.
  • Training time: the 16-epoch training and validation loop, including history writes and copies of best weights. It excludes dataset preparation, post-training fixed-weight metrics and final artifact generation.
  • Inference time: the median of three complete batched passes after one warmup, divided by image count. It includes DataLoader iteration, the forward pass and argmax; it excludes metric calculation.

Inference measures batched CPU throughput, not single-request latency. Measurements appear in results and analysis.

7. Recorded environment

The runs use two recorded environments. Both use PyTorch 2.14.0, scikit-learn 1.9.1, four CPU threads and float32 computation.

  • Main and ablation runs: the 25 main runs (4 Oct 2026) and the 15 ablation runs (5 Oct 2026) record Python 3.11.16, NumPy 2.4.6 and macOS-15.6.1-arm64-arm-64bit (commits 3c06e59 and 92f65c7).
  • Extension runs and post-results analysis: the 45 extension runs (26 Oct 2026) and the post-results analysis record Python 3.12.13, NumPy 2.5.3 and macOS 26.7.1 arm64 (commit 4f6a1f5 with the extension code, committed later as 7bde7de).

Timings are compared only within one environment. A difference between an extension run and a main run combines the changed factor with a software change. Processor model and memory are not recorded.

8.5 Reconstruct a saved model without retraining

Reload the seed-42 CNN with its saved split and normalization. The script measures test accuracy and macro-F1. Change folder for another model or seed. For an ablation model, do these three steps:

  1. Import its class from train_budget.py, for example from train_budget import CNNBudget.
  2. Add the saved run name to classes, for example "CNNBudget25k": CNNBudget.
  3. Set folder to a run folder in Assignment1/outputs_budget/.
.venv/bin/python - <<'PY'
import sys
from pathlib import Path
import torch
sys.path.insert(0, "Assignment1")
from data_loader import get_data_loaders
from evaluate import predict
from models.linear import LinearClassifier
from models.mlp import MLP
from models.cnn import CNN
from models.lstm import LSTMClassifier
from models.transformer import TransformerClassifier

classes = {"Linear": LinearClassifier, "MLP": MLP, "CNN": CNN,
           "LSTM": LSTMClassifier, "Transformer": TransformerClassifier}
folder = Path("Assignment1/outputs/CNN_seed42_20261004_112729_015620")
saved = torch.load(folder / "best.pt", map_location="cpu", weights_only=True)
info, data = saved["info"], saved["data"]
torch.set_num_threads(info["threads"])
torch.use_deterministic_algorithms(True)
model = classes[info["model"]]()
model.load_state_dict(saved["model_state"])
model.eval()
_, validation, test, _ = get_data_loaders(
    batch_size=info["batch_size"], seed=info["seed"],
    split=data, normalization=data,
)
metrics, labels, predictions, probabilities = predict(model, test)
print("Selected weight epoch:", saved["epoch"])
print(metrics)
PY

Top-level epoch identifies saved weights; info describes the run and selected checkpoint, even in the final-weight file. Optimizer state is absent, so reloading does not restore Adam's training state.

10. Limitations

Five training seeds on one split measure training variability only. They do not give a test of statistical significance or uncertainty across datasets. One fixed 16-epoch budget without a hyperparameter search does not find optimal configurations. Transformer selects the final epoch (16) in 4 of 5 seeds, so a longer budget can change its score.

The ablation matches parameter count only. It does not match compute: at about 25k parameters, mean fit time is 101.74 s for CNN and 4.37 s for MLP.

Saved preprocessing and deterministic algorithms support repeatability, but software and hardware can affect results and timings. Small grayscale catalog images limit generalization to color, high-resolution detail and real-world scenes.
